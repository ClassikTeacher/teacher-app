# Ревью фазы M5 «Учебный контент» (2026-10-25)

Объём: модули `files`, `content`, `homework`, контроллеры `/assignments`, `/submissions`, миграции 0015–0017.
Тесты в ходе ревью не запускались: ревью статическое, по коду.

## HIGH

- [x] **H-1. Массовые отмены не пересчитывают срок «к следующему занятию».** `AssignmentEventsHandler` слушает только
  `lesson.cancelled`, а массовая отмена (`bulk-cancel.use-case.ts`, `auto-cancel.handler.ts` — отпуск учителя, пауза и
  завершение серии, исключение из группы) публикует одно событие `cancellation.bulk` со списком `lessons`. В итоге
  `assignment_target.due_lesson_id` остаётся на отменённом занятии, и `OverdueAssignmentsJob` в момент его начала
  переводит цель в `overdue` и шлёт ученику `homework.overdue`. Пример: учитель отменил неделю на отпуск, у всех
  учеников ДЗ «к следующему занятию» стало просроченным.
  Что сделать: подписаться на `cancellation.bulk` и для каждого `lessons[i]` выполнить ту же логику, что в `lessonChanged`.
  Добавить интеграционный тест.

- [x] **H-2. Квоту хранилища нельзя освободить.** `FileMaintenanceJob.remove()` не вызывается нигде. Архивация материала
  или подборки (`materials.use-case.ts:105,139`) только ставит `archivedAt`, а файлы, сданные работы и проверенные файлы
  не удаляются вообще. `storage_usage.used_bytes` уменьшается только при очистке черновиков. Когда учитель упрётся в
  `quotaBytes` (Р-27), у него не будет способа освободить место, а ученики начнут получать `STORAGE_QUOTA_EXCEEDED`.
  Что сделать: решить продуктово (удаление материала навсегда, или удаление после архивации через N дней, или учёт
  только неархивных) и подключить `remove()`. Как минимум нужна команда «удалить материал» в StaffBot и REST.

## MEDIUM

- [x] **M-1. Сданные работы после завершения связи или блокировки остаются в очереди.** `linkEnded` и `accountBlocked`
  пропускают цели в статусе `submitted` (`assignment-events.handler.ts:69,76`; `RECOMPUTABLE` в `withdraw` тоже их
  исключает). Бывший ученик висит в «На проверке (N)» и в утренней сводке, а после «Принять» ему уходит
  `submission.reviewed` — уже без активной связи. Нужно либо снимать такие цели (`withdrawn`), либо скрывать их в
  `listUnreviewed`/`countUnreviewed` по активной связи и не уведомлять ученика.

- [x] **M-2. `file.infected` никто не обрабатывает.** `FileMaintenanceJob.rescan` публикует событие, но подписчика нет.
  Отправка заражённого файла заблокирована (`assertDeliverable`), однако учитель не узнаёт, почему материал «не
  открывается», а ученик — почему сдачу нужно переделать. Нужен обработчик: уведомить владельца, для сдачи —
  пометить файл в карточке.

- [x] **M-3. Срок «к следующему занятию» считается от `publishedAt` с горизонтом 90 дней** (`assignments.use-case.ts:316`).
  - Если задание опубликовано больше 90 дней назад, а новое занятие создано позже, `dueOf` его не найдёт: срок
    останется `null`.
  - Новый участник группы (`addTarget`) получает срок от `publishedAt`. Если первое занятие после публикации уже
    прошло, но ещё не отмечено (`scheduled`), цель сразу станет просроченной.
  Лучше считать от `max(publishedAt, now)` для `addTarget`/`recomputeDue`, кроме ветки «занятие уже прошло».

- [x] **M-4. `lesson.participants_changed` не обрабатывается.** Если ученика убрали из конкретного группового занятия,
  на которое указывает его `due_lesson_id`, срок останется на этом занятии.

## LOW

- [x] **L-1.** `assignmentBody.studentIds` и `groupIds` в REST без `.max()`: большой массив означает сотни запросов в одной
  транзакции (публикация идёт по циклу). Поставить разумный лимит.
- [x] **L-2.** `listUnreviewed` фильтрует через `inArray(targetId, SELECT … WHERE status='submitted')` по всем учителям
  и `NOT IN (SELECT …)` по всем проверкам. Стоит заменить на join, как в `countUnreviewed`.
- [x] **L-3.** `IngestFileUseCase.store` кеширует `file_id` из входящего сообщения. Для фото это id фото, и
  `sendDocument` в том же боте получит 400. Это обрабатывается повтором через `isBadFileId`, но запрос лишний.
  Кешировать только документы, как в `remember()`.
- [x] **L-4.** `features.limit(…, 'quotaBytes')` читается дважды: в `execute` и в `store`. Можно передать значение.
- [ ] **L-5.** _(бэклог M7-01)_ Скачивание читает тело целиком (`arrayBuffer`), без ограничения потока. Если `content-length` нет,
  проверка размера сработает только после загрузки. Для Bot API это терпимо (20 МБ), но стоит оставить в бэклоге M7-01.
